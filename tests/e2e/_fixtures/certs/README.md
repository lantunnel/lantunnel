# Fixture certs for E2E matrix

The 4-cell Go↔Rust matrix runs both gateways (Rust + Go) on the same host on
different ports, so we don't share a single cert across both — each gateway
serves its own self-signed cert and every client connects with
`tls_insecure: true`. This avoids forcing a CA dance for the loopback fixture
configs.

## Cert sources

- **Rust gateway (cells B, C):** `<repo-root>/certs/server.{crt,key}`
  - Self-signed, CN=`gateway-01.example.net`, 10-year validity.
  - Generated by repo bootstrap; regenerate via `regen-certs.sh` if missing.
- **Go gateway (cells A, D):** `~/github/tunnel-proxy/certs/server.{crt,key}`
  - Self-signed, generated by the Go repo's `make certs` target.
  - If missing: `cd ~/github/tunnel-proxy && make certs`.

The fixture YAMLs (`gateway-{rust,go}-loopback.yaml`) reference the cert files
by absolute path so each cell finds its own without copying.

## tls_insecure on clients

All client fixture configs set `tls_insecure: true`. This is acceptable
because:
- E2E targets are localhost-only.
- The matrix needs to point Rust clients at Go gateways (and vice versa) — no
  shared CA exists between the two repos.

For production-like cert verification testing, see Phase 6 security tasks.

## Regenerating

If `<repo-root>/certs/server.crt` is missing or expired, run:

```bash
./tests/e2e/_fixtures/regen-certs.sh
```

The script writes to `<repo-root>/certs/` and is idempotent (will overwrite
existing files when re-run, after a confirmation prompt).
